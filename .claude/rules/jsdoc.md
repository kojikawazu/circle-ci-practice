# JSDoc 規約（TypeScript）

**公開シンボル**には JSDoc を必須とする。

## 必須対象

- `export` された関数・型（`type` / `interface`）・定数
- **型のメンバー**（各プロパティ、union リテラルの各値）
- コンポーネントの **props / emits 型**（各プロパティに説明）
- **composable（`useXxx`）と、その戻り値の各メンバー** — Nuxt は auto-import されるため、**定義ファイルを開かずに使われる**。コメントが唯一の説明になる

**任意対象**: `export` されない内部関数、SFC 内に閉じた `ref` / ハンドラ関数、処理が自明な 1 行ユーティリティ。ただし意図が非自明なものは内部でも付ける（下記「混乱テスト」）。

## 型定義のコメント（型本体 + メンバー）

型シグネチャは「形」しか語らない。**意味・単位・制約・状態の定義**はコメントでしか残せない。

- **型本体**: 1 行目に「何を表す型か」を書く。
- **各プロパティ**: 型名から読み取れない情報を書く。特に **単位** / **`null`・省略の意味**（「未設定」か「該当なし」か）/ **制約・不変条件**。
  - 自明な項目（`id` 等）は省略してよい。**書くことがない項目に埋め草コメントを付けない**。
- **union リテラル**: 各値がどの状態を指すかを個別に書く。

```ts
/** API が返す Task 表現。DB 行そのものではなく、公開してよい形。 */
export type Task = {
  id: string
  /** 表示用タイトル。前後の空白は除去済み・最大 200 文字 */
  title: string
  completed: boolean
  /** 作成日時（ISO 8601 文字列）。DB の `timestamptz` を変換したもの */
  createdAt: string
}
```

## composable の戻り値

**戻り値型を明示し、コメントを型メンバー側に寄せる**。オブジェクトリテラルを直接返すと、中身は「宣言」ではなく「式」になり、コメントの置き場がなくなる。

書くのは**シグネチャから読めない情報**に限る。

- その値がいつ変わるか / 誰が変えるか
- **初期値・空値の意味**（「空配列は『0 件』であり『未取得』ではない」）
- **副作用の有無**（この関数は API を呼ぶか）
- 他の値との関係・不変条件

## 混乱テスト

判断軸は「public か否か」ではなく **「1 か月後の自分が『これは何？なぜ？』となるか」**。なるなら、内部関数でもテストコードでも "why" を残す。

- **キャスト・回避策には "why" 必須**: `as unknown as` / `@ts-ignore` / `@ts-expect-error` / マジック値 / 複雑な正規表現 / 明示的なワークアラウンド。**型を欺く・仕様を迂回する箇所は、その根拠がコードから消える**ため、コメントが唯一の記録になる。
- **テスト足場**（複雑な fixture・非自明な mock）も、意図が読み取りにくいなら付ける。

## 記述ルール

- **型は書かない**: 型は TypeScript のシグネチャが唯一の真実。JSDoc に `{string}` 等の型ブレースを併記しない。JSDoc は**意図・意味・制約**を日本語で書く。
- **要約行必須**: 1 行目に「何をするか」を簡潔に書く。
- **`@param` / `@returns`**: 引数・戻り値の意味がシグネチャから読めない場合に書く（オプション引数・デフォルト値の意味を含む）。
- **`@throws`**: 意図的に例外を投げる場合は発生条件を書く。
- 補助タグ（`@example` / `@deprecated` / `@see`）は必要に応じて使う。
