## 認証

- 本アプリは**認証なし**（単一ユーザー前提の学習用）。マルチユーザー対応はスコープ外（[`01`](./01-business-requirements.md)）。

## 認可（権限制御）

- ロール・権限制御はなし。すべての操作が誰でも可能（学習用の割り切り）。
- ただしサーバ側で入力検証は必ず行い、UI のみに依存しない方針とする（下記）。

## 入力バリデーション

`packages/shared` の zod スキーマを **UI（フォーム）と API（server/api）の双方**で再利用し、
クライアントを信頼しない（サーバでも必ず検証する）。

| フィールド | ルール |
|-----------|--------|
| title | 必須 / トリム後 1〜200 文字 / 空白のみ不可 |
| completed | 真偽値（PATCH 時） |
| id（パス） | UUID 形式 |

- 検証失敗時、API は `400 Bad Request` を返す（[`07`](./07-api-specification.md) のエラー契約）。

## データ保護

- 秘匿情報は `DATABASE_URL` のみ。**環境変数で管理**し、クライアントバンドルへ露出させない
  （`server/` 内でのみ参照。Nuxt の `runtimeConfig`/サーバ専用コードで扱う）。
- `.env` は Git 管理しない（`.gitignore`）。`.env.example` に雛形のみコミット。
- CircleCI では DB 認証情報を環境変数 / コンテキストで注入する（リポジトリに平文で置かない）。

## 脆弱性対策

- **SQL インジェクション**: Drizzle のパラメータ化クエリを用い、文字列連結で SQL を組み立てない。
- **XSS**: Vue のテンプレート補間（自動エスケープ）を用い、`v-html` を使わない。
- **依存関係**: 既知脆弱性は `pnpm audit` 等で随時確認（CI への組み込みは将来拡張）。
- **秘密情報の漏洩**: ログ・エラーメッセージに `DATABASE_URL` 等を出さない。
