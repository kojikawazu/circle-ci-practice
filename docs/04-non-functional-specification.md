## パフォーマンス要件

- 学習用のため厳密な SLA は定めない。
- ローカル開発でタスク操作（追加・トグル・削除）が体感即時（目安 < 300ms）で反映されること。
- CI のパイプライン全体（`unit` + `e2e`）が無料枠を圧迫しない時間で完了すること（目安: 合計 10 分以内）。

## 可用性・信頼性

- 本番運用は対象外（CI 構築が目的）。
- データは PostgreSQL に保存され、アプリ再起動・ブラウザリロードで失われないこと（F-5）。

## エラーハンドリング・堅牢性

| 状況 | 振る舞い |
|------|----------|
| 不正な入力（空 / 200 文字超） | API は 400 を返し、UI はエラー表示して送信を中断 |
| 存在しない ID への更新/削除 | API は 404 を返す |
| DB 接続不可・予期せぬ例外 | API は 500 を返し、UI は失敗を通知（致命的状態を残さない） |
| `DATABASE_URL` 未設定 | サーバ起動/起動時に明示的に失敗させる（黙って動かさない） |

API のステータスコード契約は [`07-api-specification.md`](./07-api-specification.md) を参照。

## ユーザビリティ要件

- キーボードでタスク追加が完結できる（入力 → Enter / ボタン）。
- 完了タスクと未完了タスクが視覚的に区別できる。
- モバイル幅でレイアウトが崩れない。

## 対応環境

- モダンブラウザ最新版（Chromium 系。E2E は Playwright の Chromium で検証）。
- Node.js 20 LTS。pnpm。Docker（ローカル Postgres）。
- CI 実行環境: CircleCI（Linux / Docker executor）。
